# Discord는 오박사로 보낸다

Discord 글 전송은 항상 봇 "오박사" 계정으로 한다. 2026-11-25에 Composio `DISCORDBOT_CREATE_MESSAGE`로 글을 보냈다가 "오박사를 통해 보내야 한다"는 지적을 받았다. 같은 일을 되풀이하지 않는다.

## 규칙

- **보내기는 `send.mjs`만 쓴다.** Composio `DISCORDBOT_CREATE_MESSAGE`, 웹훅, 직접 API 호출로 보내지 않는다. `composio-first`가 SaaS는 Composio부터라고 해도 Discord 전송은 예외다.
- **읽기는 Composio를 써도 된다.** 채널·스레드 목록(`DISCORDBOT_LIST_GUILD_CHANNELS`)과 최근 글 읽기(`DISCORDBOT_LIST_MESSAGES`)는 보내기가 아니다.
- 규칙과 값은 `~/automations/discord-delegate/`가 맞다. 보내기 전에 `channels.md`(채널 지도·멘션 ID), `INSTRUCTIONS.md`의 "글 보내기", `directory.json`·`rules.json`을 읽는다. 이 문서와 다르면 그 폴더가 맞다. 채널 지도와 사람 ID는 회사 정보라 이 공개 저장소에 두지 않는다.

## 사람에게 요청할 때는 반드시 멘션한다

작업·확인·검토·승인·답변을 사람에게 부탁하는 글은 **그 사람을 멘션해야 한다.** 멘션이 없으면 알림이 가지 않아 받는 사람이 글을 못 보고, 요청이 묻힌다(2026-11-26 오너 지시).

- `--mention <user_id>`로 준다. 본문에 그 사람의 `<@id>`가 없으면 `send.mjs`가 글머리 뒤에 붙인다. Discord는 본문에 `<@id>`가 있고 허용 목록에도 있어야 알림을 보내므로, 둘 중 하나만으로는 알림이 가지 않는다.
- **사람 본인을 멘션한다.** 사람마다 개인 에이전트 봇이 있는데, 봇만 부르면 사람에게는 알림이 가지 않는다. 오너가 함께 태그하라고 정한 봇만 사람과 같이 부른다(`channels.md`).
- 한 글에는 요청 하나와 받는 사람 한 명. 서로 다른 일을 여러 사람에게 맡기면 글을 나눈다. 같은 일을 여러 사람이 해야 하면 모두 멘션한다. 팀 전체 공지만 역할 멘션(`--mention-role`)을 쓴다.
- 첫 줄에 무엇을 해 달라는지와 기한을 쓰고, 배경과 링크는 그 아래에 둔다.
- `send.mjs`가 이 규칙을 검사한다. 요청 표현("부탁", "확인해 주세요", "가능할까요" 등)이 있는데 사람 멘션이 없으면, 또는 봇만 멘션했으면 보내지 않는다. 요청이 아닌 답변·공지라 멘션이 필요 없으면 `--no-mention-ok`를 준다. 이 옵션으로 검사를 피해서 요청을 보내지 않는다.
- 요청받을 사람이 누구인지 모르면 추정하지 않고 사용자에게 묻는다.

## 어디에 보낼지

`~/automations/discord-delegate/channels.md`의 "어디에 보낼지" 표로 고른다. 큰 갈래는 이렇다.

- Linear 이슈를 맡아 하는 일 → 이슈 전용 스레드(`obaksa` 스킬)
- 남에게 맡기는 개발·인프라 작업 → 그 주제의 도메인 채널 스레드, 없으면 개발 요청 채널
- 도메인 논의·공유 → 해당 도메인 채널, 회의 → 회의 요청 채널, 그 밖의 문의 → 기타 문의 채널
- 알럿 채널은 알럿 글의 스레드 안에서만 쓰고, 개인 체크아웃·잡담 채널에는 오박사가 먼저 쓰지 않는다
- 오너에게만 하는 보고 → 오너의 에이전트방

그 주제의 스레드가 이미 있으면 새 글 대신 거기에 쓴다. 사용자가 채널을 말하지 않았으면 지도로 고른 채널을 초안과 함께 보여 준다. 맞는 곳이 둘 이상이거나 하나도 없으면 묻는다. 틀린 채널의 글은 되돌릴 수 없다.

## 보내는 법

```
cd ~/automations/discord-delegate
printf '%s' "본문" | doppler run -p saladlab -c dev -- node send.mjs <channel_id> [--reply <message_id>] [--mention <user_id>]... [--mention-role <role_id>] [--no-mention-ok]
```

- 본문은 stdin으로만 넘긴다(백틱·따옴표가 셸에서 깨진다). 1~2000자.
- 보내기 전에 `SEND_DRY_RUN=1`을 붙이면 보내지 않고 실제로 나갈 본문(붙인 멘션 포함)과 검사 결과만 본다.
- 토큰은 Doppler `saladlab/dev`의 `DISCORD_BOT_TOKEN`이다. 출력하거나 파일에 저장하지 않는다.
- 성공하면 `{"id","channel_id"}` 한 줄이 나온다. 그 글 ID를 사용자에게 알린다.

## 보내기 전에

1. **채널을 고른다**(위 "어디에 보낼지").
2. **멘션할 사람의 ID를 확인한다.** `channels.md`의 사람 표에 없으면 그 채널의 최근 글 작성자에서 찾는다. 이름이 같은 계정이 둘 이상이면(사람과 그 사람의 봇 등) 어느 쪽인지 사용자에게 알린다.
3. **오너 이름으로 결정하거나 약속하는 글을 쓰지 않는다.** 사용자가 시킨 사실 전달과 요청만 한다.
4. **근무 시간(`rules.json`의 `work_hours`) 밖에는 멘션이 들어간 글을 보내지 않고** 사용자에게 미룰지 묻는다. 멘션 없는 글은 보내도 된다.
5. **초안을 사용자가 못 봤으면 먼저 보여 준다.** 채널, 멘션할 사람, 본문을 함께 보여 준다. 사용자가 문구까지 정해 주었거나 "그대로 보내"라고 한 경우만 바로 보낸다.

## 글머리

`rules.json`의 `prefix`(`[오한준 대리 · {issue}]`)는 Linear 이슈를 맡은 작업(`obaksa` 스킬)의 글에 붙인다. 이슈와 무관한 일회성 전달에는 이슈 번호가 없으므로 사용자에게 글머리를 붙일지 한 번 묻는다. 묻지 못하면 오박사가 보냈다는 점이 보이도록 이슈 번호 없이 `[오한준 대리]`로 시작한다.

## 이슈를 맡아 스레드로 일하는 경우

이슈 전용 스레드, 수신 데몬, 상태 리액션, 승인 판정, 재촉은 `obaksa` 스킬을 쓴다. 이 스킬은 "한 번 보내기"만 다룬다.
