# 새 구현 작업의 재사용·최소 완결 변경

새로 시작하는 구현 작업에만 적용한다. 진행 중인 이슈·PR의 후속·재개는 기존 계약을 유지한다.

- **재사용 우선:** 변경과 관련된 기존 함수·컴포넌트·서비스·패턴과 설치된 의존성을 먼저 확인한다. 호출부·인터페이스·동작·권한·승인된 UI에 맞으면 재사용한다. 맞는 구현이 없으면 표준 라이브러리·플랫폼 기능을 검토하고, 요구사항을 충족하는 데 필요한 새 구현·의존성만 추가한다.
- **최소 완결 변경:** 승인된 목표와 완료 기준을 전부 충족하는 가장 작은 변경을 만든다. 영향받는 호출부·타입·export·설정·fixture도 함께 맞춘다. 요청하지 않은 기능·옵션·추상화·래퍼·향후 범용화는 추가하지 않는다. 줄 수를 줄이려고 가독성이나 필요한 동작을 희생하지 않는다.

기존 모델·계획 비평·테스트 작성·독립 검증·리뷰·완료 증거·승인 범위는 바꾸지 않는다. 검증·오류 처리·데이터 손실 방지·보안·접근성과 승인된 UI를 최소화 대상으로 삼지 않는다. 보고는 기존 간결한 보고 규칙을 따른다.

첫 완료된 새 구현 작업 5건은 기존 메인 루프 관찰에 함께 포함한다. 기존 완료 기록·로그에서 재사용한 항목 또는 새 구현 이유, 변경 범위, 재작업·검증 및 리뷰 결과와 확인 가능한 역할별 입력·캐시·출력 사용량을 확인한다. 증거가 없으면 미확인으로 남기고, 같은 종류·위험도·모델·추론 강도의 이전 작업과 비교 가능한 경우에만 차이를 살펴본다. 진행 중인 작업은 표본에서 제외하며, 별도 감시 에이전트·모델 호출·자동 후킹은 추가하지 않는다.

Ponytail 5.3.3의 [재사용·최소 변경 원칙](https://github.com/DietrichGebert/ponytail/blob/main/skills/ponytail/SKILL.md)을 참고한 로컬 규칙이다. 외부 원문을 매 작업 다시 불러오거나 플러그인·모드·자동 후킹을 설치할 필요는 없다.
