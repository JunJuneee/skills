# 새 저위험 구현의 Sonnet medium 시험

사용자가 승인한 이 시험은 **이 기기에서 새로 시작하는 저위험·소규모 구현 최대 3건**에만 적용한다. 정본 상태는 이 기기에 미리 초기화된 로컬 `~/.traycer/sonnet-medium-implementation-v1.sqlite3`이다. 다른 호스트에서 독립 장부를 만들거나, 장부·호스트·슬롯 상태를 확인할 수 없을 때는 시험하지 않고 기존 구현 모델 계약을 따른다. 예약된 세 작업이 끝나면 추가 시험 없이 기존 기본값을 사용한다.

## 대상과 제외

- 범위와 완료 기준이 분명하고, 실패 영향이 작으며 쉽게 되돌릴 수 있는 새 소규모 버그 수정이나 국소 변경을 대상으로 한다. 영향 범위가 불명확하거나 피해가 클 수 있으면 제외한다.
- 인증·권한·결제·비밀·개인정보, 운영 데이터·DB 마이그레이션, 장애 복구, 광범위한 아키텍처·리팩터링, 복잡한 원인 분석 등은 제외한다. 예시만으로 위험을 자동 판정하지 않고 실제 영향과 되돌림 가능성을 확인한다.
- 진행 중인 이슈·PR과 같은 작업의 후속·재개는 제외하고 기존 계약을 유지한다. 사용자가 별도 구현 모델·추론 강도를 지정했거나 프로젝트의 필수 모델 계약과 충돌하면 그 계약을 우선한다. 현재 사용자 요청으로 실제 작업이 승인됐는지도 별도로 확인한다.

## 착수와 3건 상한

1. 조율자가 기존 이슈·PR·소유·승인 범위와 위험도를 확인하고, 실행 호스트에서 `traycer_list_harness_models`와 허용 프로필을 확인한다. 최신 사용 가능한 Claude Sonnet과 `medium`이 지원되지 않으면 기존 구현 계약을 따른다. `sonnet` 별칭만으로 특정 버전을 단정하지 않고, 결과 수락 전 실행 transcript에서 실제 모델을 확인한다. 확인할 수 없는 결과는 미검증으로 둔다.
2. 대상이 확정되고 실제 착수할 때에만 `python3 ~/.agents/skills/agent-workflow/scripts/sonnet_pilot.py reserve --task-key linear:JAY-123`처럼 예약한다. Linear 이슈는 실제 이슈 ID로, 이슈가 없으면 안정적인 작업 고유 ID를 `task:...`로 사용한다. 같은 작업은 항상 같은 표준 ID를 쓴다. 스크립트는 로컬 원자적 트랜잭션으로 1~3번을 배정하고 중복 ID를 재사용하며, 네 번째 새 작업은 거절한다. `existing: true`는 이전 예약일 뿐 새 조율자·구현자의 중복 착수 승인이 아니다. 예약은 착수·중단·실패·모델 상향 여부와 관계없이 한 건을 소모하며 자동 반환·재초기화하지 않는다. 소유와 실행이 불명확한 예약을 다른 작업으로 바꾸지 않는다.
3. 계약에 `sonnet-medium-implementation-v1`, 슬롯·작업 ID, 위험도와 근거, 실제 모델·프로필·추론 수준·계획/구현 세션, 상향 조건과 필수 검증·승인 범위를 남긴다. 슬롯은 3건 상한일 뿐 작업 착수나 외부 쓰기 승인이 아니다. `python3 ~/.agents/skills/agent-workflow/scripts/sonnet_pilot.py status`로 확인한다.
4. 계획·관련 탐색·구현·리뷰 수정은 가능한 한 같은 Claude Sonnet medium 주 실행 세션에서 진행한다. 계획 critique 계열은 실제 구현 하네스인 Claude의 반대 계열인 Codex다. 기존 3인 계획 critique, 별도 테스트 작성자와 독립 실행 검증자, 별도 Opus 최종 리뷰, 사용자·프로젝트의 검증과 승인 범위는 바꾸지 않는다.

## 중단·상향 및 관찰

- 실질적인 요구사항 누락·반복 실패·범위 확장·위험 증가가 확인되면 조율자는 새 시험 착수를 중지하고 `python3 ~/.agents/skills/agent-workflow/scripts/sonnet_pilot.py pause --reason '짧은 사유'`로 기록한다. 비밀이나 원문은 넣지 않는다. 이미 진행 중인 다른 작업의 계약을 자동 변경·중단하지 않는다. 해당 작업은 범위와 기존 승인을 지키며 원인을 기록하고, 필요하면 같은 Claude 계열 Opus xhigh로 상향해 계획 변경이 실질적이면 기존 계획 critique 절차를 다시 거친다. 필요한 테스트·독립 검증·Opus 리뷰를 계속 수행한다. 상향·실패도 원래 슬롯과 해당 작업의 총 사용량에 포함한다. 해제·새 시험은 별도 사용자 지시가 있을 때만 한다.
- 기존 완료 증거와 로그로 모든 역할·재시도의 모델/세션, 입력·캐시 생성·캐시 읽기·출력, 완료 시간, 오류·재작업·검증 및 리뷰 결과를 기록한다. 접근할 수 없는 사용량은 미확인으로 남기고 세션별 추정치를 작업에 무리하게 배분하지 않는다. 비슷한 종류·위험도·검증 계약의 이전 작업과 비교하되 구현 모델 차이와 작업량 차이를 명시한다. 3건은 탐색적 표본이며 절감률을 단정하지 않는다. 별도 벤치마크 모델 호출·감시 에이전트·자동 후킹은 설치하거나 실행하지 않는다.
