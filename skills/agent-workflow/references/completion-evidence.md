# 완료 증거

## 사실 게이트

계획·결정에 쓰는 데이터 주장은 실제 읽기 전용 쿼리와 원본 출력, 수치, 실행 시각, 데이터 기준 시각으로 확인한다. 표의 “쿼리/수치/시각” 칸을 채운 것만으로는 실측이 아니다. 예를 들어 서울 밖 데이터가 부족하다는 주장은 전체 분포를 세고 나서 사용한다.

완료 기준별 측정은 command·UI·data 등 실제 방법으로 연결한다. UI의 viewport 축소는 실기기 키보드 확인을 대체하지 않는다. mock이 제공하지 않는 endpoint나 화면은 별도 방법으로 확인하거나 UNVERIFIED로 남긴다. 기존 테스트 실패·skip·확인 범위도 원본에 보존한다.

## 역할 보고 계약

자동 판정에 연결할 때는 runner가 역할별 호출 ID와 **완료된 결과**를 연결한다. Agent 호출이 존재하거나 본문 어딘가에 PASS 문자열이 있다는 이유로 인정하지 않는다. 다른 세션·늦은 비동기 notification·미완료 호출이 최상위 결과를 덮지 않게 한다.

프로젝트에 기계 보고 형식이 있으면 그대로 쓴다. 새 계약은 다음과 같이 명확히 버전과 대상을 적는다.

```text
VERDICT: {"version":1,"role":"reviewer","status":"PASS","sha":"<full-sha>","tree":"<tree-sha>","base_sha":"<review-base-sha>"}
```

검증자는 `role:"verifier"`로 제출 SHA·tree와 AC별 근거를 보고한다. FAIL과 UNVERIFIED를 PASS로 바꾸지 않는다. 구조화된 완료 메타데이터가 있는 로그는 그 status·역할·실제 보고 content를 읽는다. 사용자용 hand-back 래퍼·들여쓰기와 실제 보고를 구분한다. 메타데이터가 없는 구형 로그는 호출 완료를 입증할 수 있는 프로젝트 계약이 없는 한 확인불가로 남긴다.

리뷰 대상과 **최종 제출 tree·비교 기준**이 바뀌면 달라진 내용을 다시 리뷰한다. WIP SHA가 달라도 tree·base가 동일하면 계약이 허용하는 범위에서 검토 근거를 재사용할 수 있다. tree가 바뀐 리뷰 PASS를 최종 결과로 재사용하지 않는다. 검증 보고는 제출 SHA를 사용한다.

## runner의 독립 검사

세션 작업 폴더 대신 제출 SHA로 새 detached worktree를 만든다. PR의 head·실제 base와 main 기준을 기록한다. 검증 전용 작업은 PR이 없더라도 고정 SHA와 측정 기준으로 검증할 수 있다.

- 검증 home에는 **제출 코드 버전**의 데이터 레이어·스크립트를 넣는다. 예전 실행본 코드와 새 프런트엔드를 섞어 통과시키지 않는다.
- 기존 DB를 읽기 전용으로 사용한다면 원본의 hash·mtime을 전후 비교한다. DB 재생성·운영 반영이 필요한 변경은 별도 범위와 증거로 구분한다.
- 기본 자동 검사는 mock·LLM 없는 API로 수행한다. 실 LLM 요청은 사용자의 허용 범위와 질의 수로 제한한다.
- checker의 실제 OS returncode와 필수 단계별 executed·returncode·skip 사유를 보존한다. stdout의 `rc=0`이나 verifier의 자기 보고를 최종 기준으로 삼지 않는다.
- 필수 모듈·데이터 레이어·Chromium 부재로 검사가 통째로 skip되면 성공이 아니다. 허용 xfail·부분 skip은 실제 이유와 계약을 대조한다.
- 시작·종료 때 HEAD가 제출 SHA인지, 추적·미추적 소스가 바뀌지 않았는지 확인한다. .venv·빌드 결과 같은 허용 생성물은 프로젝트 기준으로 구분한다.
- PR head는 검증 시작·종료·증거 발급 직전에 확인한다. 발급 후 주기적 polling은 필요성이 확인된 프로젝트에서만 추가한다.

원래 유형·완료 기준과 발급 직전 값도 대조한다. snapshot hash 엔진을 기본으로 만들 필요는 없지만, 바뀐 완료 기준을 예전 증거로 충족했다고 주장해서는 안 된다.

## 보존과 판정

증거 JSON에 제출 SHA/tree·PR/base, 역할 결과, 원래 완료 기준, 기준별 실측 경로, checker 단계·실제 종료 코드, 환경·데이터 시각, 오류, 발급 시각·모드를 기록한다. 파일명은 `evidence/<issue>-<sha>.json` 같은 프로젝트 계약으로 정한다.

준비 API 오류는 검증 불합격과 구분하고 제한된 재시도로 처리한다. 부분 필드가 없다고 수집 코드가 매 tick 예외를 내며 무한 대기하지 않게 한다.

증거를 발급한 뒤 게시 API만 실패하면 **발급된 판정을 고정하고 게시만 재시도**한다. 같은 발급을 재수집해 PASS→FAIL로 덮거나 실패 카운터를 재시도마다 더하지 않는다. 사람이 hold·취소·완료 기준을 바꾸면 게시 전에 우선 확인한다. runner 자신이 게시 중 쓴 Todo/blocked와 사람의 변경을 구분한다.

observe는 기존 판정을 유지한다. enforce의 실패 상태·라벨 변경은 프로젝트가 승인한 계약대로만 한다. 검증 오류 때문에 상태 기반 성공 판정으로 조용히 되돌아가지 않는다.
