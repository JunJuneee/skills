# 결과물 전달

## 정적 묶음부터

기본 결과물은 발급 증거, 세션의 공개 가능한 최종 보고, 기준별 출력, UI 스크린샷을 포함한 정적 페이지다. 요약 에이전트나 이슈별 live 서버를 먼저 추가하지 않는다. `bundles/<issue>-<sha>/index.html` 같은 경로를 프로젝트에서 정한다.

페이지에는 검증 대상 SHA·시각, 실제 동작 변경, 확인 방법과 기대 결과, 기준별 PASS/FAIL/UNVERIFIED, 리뷰·테스트 결과, PR 링크, 배포·실행본 반영 필요 여부를 표시한다. 특정 SHA를 검증했다는 표현을 사용하고 현재 PR의 모든 후속 커밋까지 검증한 것처럼 쓰지 않는다.

원본을 가리키기만 하지 말고 허용된 근거를 bundle 내부에 복사한다. 폴더 이동·원본 삭제 뒤에도 페이지·이미지·링크가 열리는지 확인한다. 실패·근거 누락은 incomplete로 진단하며 ready로 숨기지 않는다.

## 공개 가능한 파일 경계

작업자가 자유롭게 지정한 경로를 모두 복사하지 않는다. 지정 scratch 안의 허용된 측정 파일만 읽고 symlink 탈출을 검사한다.

- `.env`, 키·토큰 파일, 원본 세션 JSONL, DB 등 민감 파일을 포함하지 않는다.
- 복사된 `stdout.txt`만 보고 안전하다고 판단하지 않는다. 원래 경로와 resolve한 출처의 이름·허용 범위를 확인하고 그 provenance를 발급 시 보존한다. benign.txt가 .env를 가리키는 alias도 거부한다.
- 과거 보존본에 provenance가 없고 원본 출처도 없어 검증할 수 없다면 incomplete로 둔다.
- 허용 stdout에도 비밀 값이 섞일 수 있다. 민감 값이 없는 보고·출력만 전달한다. 파일명 검사만으로 내용의 안전성을 보장하지 않는다.
- HTML escaping과 상대 경로 링크를 사용한다. UI 기준은 스크린샷 존재·읽기·실제 이미지 디코딩을 확인한다.

새 발급이 같은 SHA에서 FAIL이 된 경우 페이지도 그 발급에 맞춰 갱신한다. **동일한 발급**을 다시 만들다가 원본이 사라진 경우에는 기존 정상 bundle을 망가뜨리지 않는다. staging 후 교체하며 기존 디렉터리 이동부터 예외 복구 범위에 포함한다. 프로세스 crash 복구가 필요한 운영에서는 그 수준에 맞는 immutable 저장·포인터 방식 등을 선택한다.

## 외부 게시

생성과 게시 모드를 나눈다. observe에서는 파일만 만들고 허용되지 않은 Linear 코멘트·PR 본문 편집을 하지 않는다. 게시가 승인됐다면 발급 키를 기준으로 기존 댓글을 pagination 조회해 중복을 막는다.

동일 이슈/SHA의 조회→생성→게시 결과 기록을 한 잠금 범위로 처리한다. API 응답 유실은 즉시 중복 생성하지 않고 같은 키를 재조회한다. durable manifest에 실제 게시 상태·댓글 ID·재시도 횟수를 남기고 재시도 상한을 둔다. 상한을 넘으면 전달 실패를 남기며 증거 판정은 보존한다.

**게시 직전** 현재 hold·결정 대기·취소·완료 기준을 확인한다. 조회를 기다리는 사이 바뀔 수 있으므로 mutation 직전에 다시 확인할 수 있는 경계를 둔다. 게시가 보류됐어도 로컬 증거·bundle은 보존한다. CLI 출력도 실제 게시 반환값을 반영한다.

원격에 로컬 경로를 남겼다면 로컬 파일이라고 설명한다. 원격 사용자도 열 수 있는 공개 URL이 생겼다고 주장하지 않는다.

## 미리보기는 별도 단계

미리보기 자동화가 요청됐을 때만 지정 PR 목록과 SHA로 합류 코드를 준비한다. 원본 데이터는 읽기 전용, 제출 버전의 스크립트·빌드·의존성을 사용한다. 자동 준비·health check는 실 LLM 질의를 하지 않는다.

사용자가 직접 쓰는 실 LLM 미리보기와 자동 mock 증거를 구분한다. 이미 e2e 스크린샷으로 확인할 수 있다면 별도 mock live 서버는 필수가 아니다.

기존 서버의 최초 소유권 전환은 실제 PID·명령·소유 정보를 확인해 별도 절차로 한다. **포트만 보고 기존 서버를 kill하지 않는다.** 새 구성을 먼저 준비·검증한 뒤 교체하며 기동 실패 시 이전 구성으로 복구한다. 지정 보호 포트·실행본을 유지한다.

미리보기에 합류하지 못했다면 “미리보기 전달 완료”를 선언하지 않는다. 결과 페이지 생성 성공, 게시 성공, 미리보기 성공은 각각 보고한다.
