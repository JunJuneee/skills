# 작업 계약

## 승인 범위

- 목표:
- 변경할 동작과 범위:
- 대상 저장소·기준 브랜치:
- 이번 지시에 포함된 외부 작업: 카드 생성 / PR 작성 / 병합 / 배포 / 게시 중 승인된 것
- 제외 사항:
- 합의된 예산·작업 수 상한: 미설정이면 미설정이라고 기록
- 예외와 만료 조건:

## 프로젝트 연결

- 작업 관리 도구·프로젝트·팀:
- 현재 상태 이름과 자동 실행 대상:
- 사용자 결정 / 실행 보류 / 실패 / 실행 중의 실제 라벨:
- runner·설정·활성 job 확인 방법:
- 코드 저장소와 데이터·실행본의 관계:
- 기존 evidence·delivery 모드, 신규 기능 도입 모드:
- 검증 명령·필수 단계·허용 skip:
- 근거 scratch 경로와 보존·결과물 경로:
- mock 방법·실 LLM 사용 조건:
- 보호할 서버·포트·DB:

값은 현재 환경에서 확인해 채운다. 이 템플릿의 항목은 설정을 바꾸라는 지시가 아니다.

## 작업 목록

| 카드 | 재사용/신규 | 동작·완료 기준 | 선행 | 실행 담당 | 판정·근거 |
| --- | --- | --- | --- | --- | --- |

관찰 가능한 완료 기준에 AC1부터 ID를 붙인다. “보고서 제출”, “결과 페이지 생성” 같은 전달 절차는 구현 동작의 AC와 구분한다. 검증 시점에 아직 없는 최종 보고서를 검증 대상으로 요구하지 않는다.
