# 에이전트 작업 지시

## 목표와 역할

- 사용자에게 이미 승인된 목표:
- 이번 역할: 구현 / 테스트 작성 / 독립 코드 리뷰 / 검증 중 지정
- 대상 카드와 작업 유형:
- 완료 기준: 원래 카드의 AC ID·본문을 그대로 포함

## 작업 환경

- 저장소와 격리 worktree:
- 변경 허용 파일·범위:
- 수정하지 않을 파일·설정·DB·서버:
- 기준 브랜치와 전체 SHA:
- 검토·검증 대상 전체 SHA/tree:
- 실제 PR 비교 기준 SHA:
- source의 immutable 원본 핀: 원본 무수정 조건이 있을 때만
- 근거 scratch의 **확인된 절대 경로**:
- 결과·리뷰 문서 저장 경로:
- mock·검증 명령·필수 단계·허용 skip:

scratch는 상위 실행기가 정한 경로를 그대로 전달한다. 셸이 TMPDIR를 바꾸더라도 근거가 다른 곳에 저장되지 않게 한다. 프로젝트가 AUTORUN_SCRATCH 같은 전용 env를 쓴다면 그 값을 확인하고 모든 자식에게 전한다.

## 허용 작업

- 구현자는 지정 범위의 코드와 필요한 검증만 수행한다.
- 테스트 담당자는 합의된 테스트 파일만 수정하고 제품 코드를 대신 고치지 않는다.
- 독립 리뷰어는 대상 코드를 읽고 temp/mock 반례와 리뷰 기록을 만든다. 별도 승인 없이 소스·API·운영 데이터를 수정하지 않는다.
- commit / push / PR 작성 / 병합 / 게시 중 이번 역할에 위임한 작업:
- 결정이 필요한 경우의 전달 경로와 멈출 범위:

기존 승인 범위 안의 통상적인 판단은 진행한다. 권한·새 정책·데이터 보관·비용의 실제 경계가 나오면 해당 부분만 보류하고 질문이나 결정 카드에 근거를 남긴다.

## 회신

- 최종 대상 SHA/tree·base와 변경 파일:
- 실제 실행한 명령·returncode·테스트 수·skip:
- 기준별 PASS / FAIL / UNVERIFIED와 원본 출력·이미지 경로:
- 검토 결과와 재현한 발견:
- 아직 수행하지 않은 작업:
- 보고 대상·응답 ID: 현재 환경에 비동기 회신 계약이 있을 때만

자동 판정에 쓰는 reviewer·verifier는 프로젝트의 버전 있는 VERDICT 계약을 지킨다. 본문에 PASS만 적거나 호출 시작만 알리는 보고는 완료 증거가 아니다. 부모는 회신을 실제 최종 코드와 대조하고, 의미 있는 변경 후에는 달라진 부분을 다시 검토한다.
