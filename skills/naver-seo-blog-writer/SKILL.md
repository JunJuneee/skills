## 기존 Blogger 글 연동

네이버 글을 작성할 때는 먼저 `references/blogger-post-index.md`를 읽어 기존 발행글의 제목·URL·해시태그를 확인한다. 사용자가 기존 주제의 재작성·확장·후속 글을 요청했거나 주제가 명확히 겹치면 `references/blogger-post-archive.json`에서 해당 원문을 읽고, 사실관계·구성·핵심 키워드를 인계받아 네이버용으로 새롭게 작성한다. 같은 세션에서 Blogger 글을 새로 발행했다면, 먼저 `/Users/jun/Desktop/skills/mcp-blogspot-posting/export-posts-for-naver.py`를 실행해 아카이브를 갱신한다.

아카이브의 글을 그대로 복제하지 않는다. 네이버 검색 의도와 최신 정보에 맞춰 재구성하며, 기존 URL은 내부 참고용으로만 쓴다. `함께 보면 좋은 글`에는 첫 번째 항목으로 [홈쇼핑 편성표 확인하기](https://homeshopick.com/)를 넣고, 추가 관련 글은 사용자가 요청한 경우에만 작성한다. 글의 마지막에는 Google Blogger URL을 별도로 노출하지 않는다. 새로 발행한 Blogger 글이 있으면 네이버 작업 전 아카이브를 최신 상태로 갱신한다.

# 기본 게시용 출력 규칙 (최우선)

이 절의 규칙을 앞선 기본 출력 템플릿보다 우선 적용한다.

## 구분선

기본 게시용 원고에서는 `---` 구분선을 모든 H2 소제목 바로 위에 한 번 넣는다.

문단, 표, 체크리스트 항목, FAQ 질문 사이에는 구분선을 넣지 않는다.

도입부와 첫 H2 사이에는 첫 H2 바로 위에 구분선을 넣는다.

H3 위에는 구분선을 넣지 않는다.

FAQ, 마무리, 함께 보면 좋은 글, 공식 출처는 항상 H2로 처리하고 예외 없이 바로 위에 구분선을 넣는다.

마무리를 H3나 굵은 일반 문장으로 처리하지 않는다. 글의 마지막 정리 섹션은 반드시 실제 H2인 `## 마무리`로 작성하고, 바로 위에 `---`를 한 번 넣는다.

마크다운 출력에서는 모든 `## 소제목`의 직전 비어 있지 않은 줄이 반드시 `---`여야 한다.

네이버용 일반 텍스트 출력에서는 H2 역할을 하는 큰 소제목의 바로 앞에 `---`를 넣고, H3 역할을 하는 질문이나 세부 소제목 앞에는 넣지 않는다.

출력 직전에 아래 조건을 검사하고 누락이 있으면 자동으로 수정한다.

* 모든 H2 바로 위에 `---`가 있는가
* H3 바로 위에 불필요한 `---`가 없는가
* 연속된 구분선이 없는가
* 일반 문단이나 체크리스트 사이에 구분선이 들어가지 않았는가
* 마무리가 H2로 작성되고 바로 위에 `---`가 있는가

## H2·H3 제목 간격

H2와 H3 제목은 각각 한 줄을 단독으로 사용한다.

모든 H2와 H3 제목 다음에는 빈 줄을 정확히 한 줄 넣은 뒤 본문을 시작한다.

모든 H2와 H3 제목 앞에도 빈 줄을 정확히 한 줄 확보한다. 단, H2 바로 위에 `---`가 있는 경우에는 `---`, 빈 줄, H2 순서로 작성한다.

H2 또는 H3 제목과 첫 본문 문장을 같은 줄에 붙이지 않는다.

하나의 소주제 설명이 끝나면 빈 줄을 한 줄 넣은 뒤 다음 H3를 시작한다.

네이버 게시용 원고에서도 H2는 `## 제목`, H3는 `### 제목` 형식으로 실제 제목 계층을 유지한다.

H2와 H3를 `**제목**` 형태의 굵은 일반 문장으로 대체하지 않는다.

H2 앞에는 `---`를 넣고 H3 앞에는 `---`를 넣지 않는다.

형식:

```text
---

## 급락장에서 자주 하는 실수는 무엇일까요?

### 아래꼬리 하나로 바닥을 단정하는 경우

캔들은 하루 동안의 매매 결과만 보여줍니다. 이후 저점 유지와 수급 개선이 확인되지 않으면 바닥 판단이 성급할 수 있습니다.

### 반등률만 보고 추세가 바뀌었다고 생각하는 경우

낙폭이 컸던 만큼 단기 반등 폭도 크게 나타날 수 있습니다. 거래량과 매수 주체가 뒷받침되는지 함께 봐야 합니다.
```

출력 직전에 아래 조건을 검사하고 어긋나면 자동으로 수정한다.

* H2와 H3가 각각 독립된 한 줄인가
* 모든 H2와 H3 다음에 빈 줄 한 줄이 있는가
* 모든 H2와 H3 앞에 빈 줄 한 줄이 있는가
* 각 소주제의 설명과 다음 소제목 사이에 빈 줄 한 줄이 있는가
* 제목과 본문이 같은 줄에 붙어 있지 않은가
* H2가 실제 `##`, H3가 실제 `###` 형식으로 표시됐는가
* H2와 H3가 굵은 일반 문장으로 대체되지 않았는가

## FAQ 문단 형식

FAQ 섹션 제목은 H2로 처리하므로 바로 위에 `---`를 넣는다.

각 FAQ 질문은 실제 H3인 `### Q. 질문 내용` 형식으로 작성하며 질문 위에는 구분선을 넣지 않는다.

답변은 질문과 같은 줄에 이어 쓰지 말고 다음 문단에서 시작한다.

각 질문과 답변 사이에는 빈 줄 한 줄을 넣고, 하나의 답변이 끝난 뒤 다음 질문 전에도 빈 줄 한 줄을 넣는다.

답변은 특별한 이유가 없으면 2~4문장으로 작성한다. 결론을 첫 문장에 제시하고 이유나 예외를 이어서 설명한다.

FAQ 답변의 각 문장은 서로 다른 문단으로 작성한다. 문장과 다음 문장 사이에 실제 빈 줄을 한 줄 넣는다.

형식:

```text
---

## 자주 묻는 질문

### Q. 구마모토는 후쿠오카와 가까운가요?

규슈 안에서는 비교적 가까운 편입니다.

구마모토는 후쿠오카 남쪽에 있으며 두 도시를 규슈 신칸센이 연결합니다.

다만 지진 이후에는 평소 이동시간보다 실제 운행 여부를 먼저 확인해야 합니다.

### Q. 구마모토 지진이 오사카나 도쿄 여행에도 영향을 주나요?

두 도시는 구마모토와 거리가 멉니다.

구마모토의 강한 흔들림이 일본 전역의 여행 중단을 의미하지는 않습니다.

다만 규슈를 오가는 연결 항공편과 철도 일정에는 간접적인 영향이 생길 수 있습니다.
```

출력 직전에 아래 조건을 검사하고 어긋나면 자동으로 수정한다.

* FAQ 질문이 실제 H3인 `### Q.` 형식으로 분리됐는가
* 답변이 다음 문단에서 시작하는가
* FAQ 답변의 각 문장 사이에 실제 빈 줄 한 줄이 있는가
* FAQ 항목 사이에 빈 줄이 있는가
* FAQ 개별 질문 위에 `---`가 들어가지 않았는가

## 본문 문단 분리 형식

모바일 가독성을 위해 한 문단에는 하나의 중심 내용만 담는다.

하나의 문단이 3문장을 넘거나 서로 다른 사실·주의사항·예외를 함께 담으면 2개 이상의 문단으로 나눈다.

H2 아래의 직접적인 답변, H3 아래의 설명, 다음 H3는 각각 실제 빈 줄로 분리한다.

네이버용 본문은 한 문장당 하나의 문단으로 작성한다.

모든 마침표·물음표·느낌표로 끝나는 본문 문장 뒤에는 실제 빈 줄을 한 줄 넣는다.

새 문단은 반드시 빈 줄 한 줄로 분리해 화면에서도 서로 다른 문단으로 보이게 한다.

중심 내용이 바뀌거나 다음 소주제·FAQ·요약으로 넘어갈 때도 빈 줄을 한 줄 넣는다.

같은 중심 내용을 설명하는 문장이라도 한 줄만 바꾸어 이어 쓰지 않는다. 반드시 빈 줄을 넣어 별도 문단으로 만든다.

형식:

```text
---

## 마무리

코스피 급락 뒤에는 V자 반등과 저점 재확인이 모두 나타날 수 있습니다.

긴 아래꼬리는 저가 매수세 유입을 보여주는 신호입니다.

하지만 시장의 바닥을 확정하는 근거로 사용하기에는 부족합니다.
```

아래 내용은 같은 H2 안에서도 각각 별도 문단으로 분리한다.

* 첫 문단: 질문에 대한 직접적인 결론
* 다음 문단: 공식 발표나 구체적인 사실
* 다음 문단: 예외 또는 변동 가능성
* 다음 문단: 독자가 확인해야 할 행동

날짜가 다른 발표, 기관이 다른 정보, 교통과 숙소처럼 확인 대상이 다른 내용은 한 문단에 몰아넣지 않는다.

문단 사이에는 빈 줄 한 줄을 넣는다. 문단 사이에 `---` 구분선을 넣지는 않는다.

공식 출처명과 URL은 긴 본문 문장 사이에 붙이지 않는다. 출처를 표시할 때는 설명 문단이 끝난 뒤 별도 문단 또는 별도 줄에 배치한다.

형식:

```text
여행 가능 여부는 방문 지역과 교통편을 나누어 판단하는 것이 좋습니다.

아소 구마모토공항은 지진 당일 국내선과 국제선이 모두 결항됐다고 발표했습니다.

공항은 다음 날 정상 운항 재개를 안내했지만 일부 항공편은 결항될 수 있다고 함께 공지했습니다.

아소 구마모토공항 지진 관련 공지
https://example.com
```

## 체크리스트 문단 형식

체크리스트 항목은 `□ **확인할 항목**` 형식으로 한 줄에 작성한다.

항목이 중요한 이유나 확인 방법은 같은 줄에 이어 쓰지 말고 바로 다음 줄 또는 다음 문단에 1~2문장으로 작성한다.

각 체크리스트 항목 사이에는 빈 줄 한 줄을 넣는다.

체크리스트 항목 사이에는 `---` 구분선을 넣지 않는다.

형식:

```text
□ **이용 항공사의 운항 여부**
공항 전체가 운영되더라도 일부 항공편은 결항하거나 지연될 수 있습니다.

□ **신칸센·JR·버스 운행 상황**
안전 점검이나 도로 통제로 운행 일정이 바뀔 수 있습니다.
```

출력 직전에 아래 조건을 검사하고 어긋나면 자동으로 수정한다.

* 한 문단에 서로 다른 주제가 과도하게 섞이지 않았는가
* 3문장을 넘는 긴 문단을 적절히 나눴는가
* 출처명과 URL이 설명 문장에 어색하게 붙어 있지 않은가
* 체크리스트 항목과 설명이 별도 줄로 나뉘었는가
* 각 문단과 체크리스트 항목 사이에 빈 줄이 있는가
* H2·H3·굵은 소주제와 설명 사이에 빈 줄이 있는가
* 본문의 모든 문장이 한 문장당 하나의 문단으로 나뉘었는가
* 모든 본문 문장 뒤에 실제 빈 줄 한 줄이 있는가
* 단순 줄바꿈만 사용해 두 문장이 붙어 있지 않은가

## 네이버 복사·붙여넣기

사용자가 네이버 블로그에 바로 복사할 글을 요청하면 파일 링크만 제공하지 말고 완성된 글을 대화에 직접 출력한다.

네이버용 복사용 HTML을 생성할 때는 사용자의 별도 요청이 없어도 게시용 HTML 상단에 복사 버튼을 기본 포함한다. 버튼은 본문 영역만 선택해 복사해야 하며, 복사 성공 또는 수동 복사 안내 상태 문구를 버튼 옆에 표시한다.

복사 버튼 바로 아래의 본문에는 섹션 구분을 위한 divider(`<hr>` 또는 동일하게 보이는 구분선)를 기본 포함한다. 도입부와 각 주요 H2 사이, 마무리·공식 출처 앞에 구분선을 배치하되, 구분선을 과도하게 연속 배치하지 않는다.

복사 버튼은 외부 라이브러리 없이 `document.createRange()`, `window.getSelection()`, `document.execCommand('copy')`를 사용하는 짧은 인라인 함수로 구현한다. 버튼과 스크립트는 네이버 본문에 복사되는 본문 영역 밖에 둔다.

생성 후 다음을 확인한다.

* 버튼이 실제 본문 영역만 선택하는가
* 본문에 버튼·상태 문구·스크립트가 함께 복사되지 않는가
* 복사 실패 시 `Command+C` 또는 수동 복사 안내가 표시되는가
* 버튼이 파일을 열었을 때 바로 작동하는가
* 주요 섹션 사이에 divider가 포함되어 있는가
* divider가 본문 내용과 겹치거나 연속으로 반복되지 않는가

네이버 블로그용 원고도 H2는 `##`, H3는 `###` 형식으로 유지한다. 사용자가 명시적으로 일반 텍스트를 요청한 경우에만 제목 기호를 제거한다.

표는 모바일 가독성을 해치거나 복사 과정에서 깨질 가능성이 있으면 항목별 목록으로 바꾼다.

별도 요청이 없으면 링크는 설명 문구에 연결된 형태로 유지하되, 사용자가 일반 텍스트를 요청하면 출처명 다음 줄에 URL을 그대로 적는다.

## 최종 업데이트 표시

제목 아래에 `최종 업데이트`, `업데이트 날짜`, `작성일`, `기준일` 문구를 기본적으로 출력하지 않는다.

최신 정보는 작성 직전에 내부적으로 확인하되, 날짜 표시는 사용자가 명시적으로 요청한 경우에만 출력한다.

사용자가 날짜 표시를 요청하면 제목 바로 아래에 한 줄로만 작성한다.

## 네이버 붙여넣기용 강제 빈 문단 규칙 (최우선)

네이버 스마트에디터에 붙여넣을 HTML 또는 복사용 원고를 만들 때는 이 절을 앞선 문장별 빈 줄과 문단 분리 규칙보다 우선 적용한다.

강제 빈 문단은 필요한 위치에만 하나씩 넣는다.

* H2 아래에만 강제 빈 문단을 하나 넣는다.
* 모든 H3 위에만 강제 빈 문단을 하나 넣는다.
* H3 아래에는 강제 빈 문단을 넣지 않는다.
* H2 위에는 강제 빈 문단을 넣지 않는다.
* 체크리스트의 `□` 항목 위에만 강제 빈 문단을 하나 넣는다.
* 체크리스트의 `□` 항목과 바로 아래 설명 사이에는 강제 빈 문단을 넣지 않는다.
* FAQ의 `Q.` 위에만 강제 빈 문단을 하나 넣는다.
* FAQ의 `Q.`와 답변 사이에는 강제 빈 문단을 넣지 않는다.
* 일반 본문 문장 사이에는 강제 빈 문단을 넣지 않는다.
* 연속된 강제 빈 문단을 만들지 않는다.

HTML 복사본에서 강제 빈 문단은 `<p>&nbsp;</p>` 또는 동등하게 보존되는 빈 블록으로 구현한다.

`함께 보면 좋은 글`은 H2 아래에 [홈쇼핑 편성표 확인하기](https://homeshopick.com/)를 첫 번째 항목으로 넣는다. 사용자가 별도로 관련 글 목록을 요청하지 않았다면 그 외 하위 제목이나 목록은 출력하지 않는다.

출력 직전에 아래 조건을 검사하고 어긋나면 자동으로 수정한다.

* H2 아래에만 빈 문단이 하나 있는가
* 모든 H3, 체크박스 항목, FAQ의 Q 위에만 빈 문단이 하나 있는가
* H3 아래에 불필요한 빈 문단이 없는가
* 체크박스와 설명, Q와 답변이 불필요한 빈 문단으로 떨어져 있지 않은가
* 일반 본문과 요약 항목 사이에 강제 빈 문단이 없는가
* 함께 보면 좋은 글 아래에 요청하지 않은 내용이 남아 있지 않은가

## 이미지 삽입 제외 (최우선)

사용자가 직접 이미지를 넣는 기본 설정에 따라, 새 네이버 원고와 네이버 붙여넣기용 HTML에는 이미지를 삽입하지 않는다.

* `<img>` 태그, 이미지 파일 경로, 카드뉴스, 대표 이미지, CTA 이미지, ALT 문구, 이미지 삽입 위치 표기를 출력하지 않는다.
* 본문 텍스트, 제목 구조, 표·체크리스트·FAQ, 공식 출처만 작성한다.
* 사용자가 특정 원고에서 이미지 삽입을 명시적으로 다시 요청한 경우에만 그 요청 범위에서 이미지를 다룬다.

출력 전 `<img`, `카드뉴스`, `CTA`, `이미지 삽입` 표시가 포함되어 있지 않은지 검사한다.

## 날짜 표기 제외 (최우선)

새 네이버 원고와 네이버 붙여넣기용 HTML에는 제목 아래의 `최종 업데이트 : 날짜` 표기를 출력하지 않는다.

* `최종 업데이트`, `업데이트 날짜`, `작성일`, `기준일` 문구와 날짜 블록을 기본적으로 모두 제외한다.
* 사용자가 초안에 해당 문구를 포함해도, 별도로 날짜 표기를 유지해 달라고 명시하지 않았다면 제거한다.
* 최신성은 작성 전에 사실 확인으로 확보하고, 본문에 날짜를 표시하지 않는다.

출력 전 제목 직후와 도입부에 `최종 업데이트`, `업데이트 날짜`, `작성일`, `기준일` 문구가 없는지 검사한다.

## 체류시간·검색 확장 규칙 (최우선)

사진, 카드뉴스, 이미지 삽입 위치 표시는 기본 출력에 포함하지 않는다. 사용자가 직접 이미지를 배치한다는 설정을 유지한다.

다만 정보형 네이버 원고에는 아래 요소를 기본으로 반영한다.

* 도입 직후 실제 H2 `## 3줄 핵심 요약`을 넣고, 글 전체의 결론·핵심 사실·주의사항을 한 줄씩 총 3개로 쓴다.
* `## 마무리` 뒤에는 실제 H2 `## 3줄 요약`을 넣고, 핵심 행동·주의사항을 한 줄씩 총 3개로 다시 정리한다.
* 두 요약은 문장을 그대로 반복하지 않는다. 도입 요약은 빠른 이해용, 마지막 요약은 행동 판단용으로 쓴다.
* 본문에서 독자의 판단에 도움이 되는 지점에 인용문을 2~4개 넣는다. 인용문은 한 문장으로 짧고 구체적으로 쓰며, 연속 배치하지 않는다.
* 검색 의도가 강한 핵심 표현은 제목뿐 아니라 H2에도 자연스럽게 반영한다. 예를 들어 `수족구병 수포 약`보다 `수족구병 약은 무엇을 사용할까? 수포 관리 방법까지`처럼 실제 검색어와 독자의 질문을 함께 담는다.
* 비교·혼동 가능성이 큰 주제는 검색량과 독자 혼동을 고려해 별도 H2로 설명한다. 예: `수족구병과 구내염은 어떻게 다를까요?`.
* FAQ는 5~8개를 기본으로 하며, 가족 내 전파처럼 실제 후속 검색 가능성이 높은 질문을 최소 1개 포함한다.
* 체크리스트는 8~12개를 기본으로 한다. 개인 위생, 수건·식기 분리, 공용 물품 세척, 가족 접촉 관리, 등원·외출 자제, 진료 신호를 주제에 맞춰 포함한다.
* `함께 보면 좋은 글`은 첫 항목으로 [홈쇼핑 편성표 확인하기](https://homeshopick.com/)를 포함한다. 시리즈 후보나 추가 관련 글 목록은 사용자가 명시적으로 요청한 경우에만 본문에 출력한다.

출력 전 다음을 검사한다.

* 3줄 핵심 요약과 마지막 3줄 요약이 각각 정확히 3개 항목인가
* 이미지·카드뉴스·사진 위치 표기가 없는가
* 인용문이 최소 2개이고 연속되지 않았는가
* 체크리스트가 8개 이상인가
* FAQ가 5개 이상이며 본문과 단순 중복되지 않는가

## CTA 이미지·파란 링크 규칙 (사용자 요청 시 최우선)

사용자가 CTA 또는 외부 연결 링크 삽입을 명시적으로 요청하고 URL을 제공한 경우에만 이 절을 적용한다.

* CTA는 도입문 마지막 문단 뒤, `## 3줄 핵심 요약`의 구분선 바로 위에 배치한다.
* CTA는 반드시 두 개의 독립 요소로 만든다. 첫째는 CTA 이미지, 둘째는 그 아래 파란색 밑줄 링크 텍스트다.
* CTA 이미지 아래의 파란색 링크 텍스트는 모바일에서도 눈에 띄도록 `font-size:20px` 이상과 굵은 글씨를 기본 적용한다.
* CTA 이미지 안에는 `자세히 보러가기`와 해당 주제의 짧은 검색어를 넣되, 파란 링크 문구는 이미지 안에 넣지 않는다.
* CTA 이미지와 이미지 아래의 파란색 텍스트는 같은 제공 URL로 각각 연결한다.
* 최하단 CTA 링크는 넣지 않는다. CTA는 도입부의 이미지 링크와 이미지 아래 파란색 링크만 유지한다.
* 파란 링크 텍스트는 가운데 정렬하고, 제공받은 URL을 그대로 연결한다.
* 네이버가 붙여넣기 과정에서 CSS 크기를 무시할 수 있으므로 CTA 이미지는 원본 파일 자체를 최대 400×400px로 만든다. HTML의 CSS 축소만으로 처리하지 않는다.
* 이미지 내부의 CTA 제목과 버튼 묶음은 상·하 여백이 같도록 세로 중앙에 맞춘다. 이미지 높이는 400px 이하이면 된다.
* HTML의 `<img src>`에는 사용자 컴퓨터의 로컬 경로를 쓰지 않는다. `CLOUDINARY_URL`이 설정돼 있으면 이미지를 Cloudinary에 업로드해 `https://res.cloudinary.com/...` 공개 URL을 사용한다.
* 업로드에 쓰는 Cloudinary API 비밀값은 출력, HTML, 로그, 답변 어디에도 노출하지 않는다.
* 공개 URL, 이미지 실제 가로·세로 크기, 이미지와 파란 링크가 분리됐는지, 도입부 CTA만 존재하는지 생성 뒤 검증한다.

기본 이미지 제외 규칙은 유지한다. 사용자가 CTA 또는 이미지 삽입을 명시하지 않은 원고에는 CTA를 넣지 않는다.

## CTA HTML 링크 노출 방지·검증 (사용자 요청 시 최우선)

CTA 링크를 HTML에 넣을 때는 제공받은 URL을 화면 본문에 그대로 출력하지 않는다.

* 제공 URL은 CTA 이미지와 파란 링크 텍스트의 `<a href>` 속성에만 사용한다.
* 상단 CTA의 이미지와 파란 링크 텍스트는 각각 같은 URL을 연결한다.
* CTA 링크 문구는 주제에 맞게 작성한다. 예: `수건 냄새 제거 방법 자세히 확인하기`.
* CTA 이미지는 상단에 한 번만 넣고, 이미지 아래 파란색 링크 텍스트만 둔다.
* 원고 HTML의 CTA URL은 총 2회만 사용한다. 상단 이미지 링크 1회, 상단 파란 링크 1회다.
* 최하단 CTA 링크는 사용자가 별도로 요청해도 기본적으로 추가하지 않는다. 사용자가 명시적으로 하단 링크를 요청한 경우에만 예외 적용한다.
* 생성 후 제공 URL이 `<a href>` 이외의 본문 텍스트·이미지 ALT·로컬 파일 경로에 들어가지 않았는지 검사한다.

### CTA 최종 점검

저장한 HTML을 제출하기 전에 다음을 반드시 확인한다.

* Blogger CTA URL은 상단 이미지 링크 1회와 이미지 아래 파란색 링크 1회, 총 2회만 존재한다.
* `공식 출처`, 해시태그, `함께 보면 좋은 글` 아래 등 문서 최하단에는 CTA 링크·링크 미리보기·CTA 카드가 없어야 한다.
* `함께 보면 좋은 글`에는 [홈쇼핑 편성표 확인하기](https://homeshopick.com/)를 첫 번째 항목으로 둔다. 사용자가 요청하지 않은 추가 bullet·관련 글·CTA는 넣지 않는다.
* 브라우저에서 하단 링크 카드가 보이면 저장된 HTML에서 실제 `<a href>` 위치를 먼저 검색한다. HTML에 하단 링크가 없으면 이전 탭 또는 캐시의 미리보기일 수 있으므로 파일을 닫고 다시 연다.
* URL 개수가 2회를 초과하거나 최하단 CTA가 발견되면 전달 전에 제거하고 재검사한다.

## 고정 CTA 템플릿·키워드 렌더링 (CTA 요청 시 최우선)

CTA가 기존 디자인의 `자세히 보러가기` 검색창 형식이면 매번 생성형 이미지를 만들지 않는다.

* skill의 `assets/cta-base-400.png`를 고정 배경으로 사용한다. 이 파일의 제목·검색창·돋보기·손가락·여백·비율은 변경하지 않는다.
* 검색창 안의 키워드만 굵은 초록색으로 입력한다.
* `scripts/render_cta_keyword.py "키워드" "출력경로.png"`로 400×400 PNG를 생성한다.
* 키워드는 공백과 기호를 포함해 `스파이더맨 4 개봉·관람 순서`와 같은 최대 16자까지만 허용한다.
* 16자를 넘으면 자동 축소·두 줄 처리하지 않는다. 의미를 유지한 짧은 검색어로 압축하거나 사용자에게 짧은 키워드를 요청한다.
* 키워드는 검색창의 흰 영역 중앙에 배치하며, 좌우 최소 여백을 유지한다.
* 생성 뒤 실제 크기가 400×400인지, 키워드가 검색창 테두리·돋보기·손가락과 겹치지 않는지 확인한다.
* 디자인 자체를 변경하거나 새 CTA 스타일이 필요할 때만 이미지 생성 도구를 사용한다.
