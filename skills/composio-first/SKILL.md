# Composio First

연결된 SaaS 작업은 **Composio부터 확인하고, 필요한 기능·계정·권한을 충족하면 그 경로로 실행**한다. 곧바로 브라우저·개별 서비스 CLI·직접 API로 넘어가지 않는다. 이 규칙은 접근 경로를 정하며, 게시·전송·병합·삭제 등의 승인 범위를 늘리지 않는다. 이미 승인된 작업을 다시 승인받는 단계도 만들지 않는다.

## 접근 경로 선택

1. 사용자가 특정 도구·계정·봇을 명시했다면 그 지시를 우선한다. 프로젝트의 작업 전용 capability·기존 실행기 계약도 유지한다. 예를 들어 제이지 봇 발신을 사용자 OAuth 연결로 대체하지 않는다. 지정된 신원과 전용 경로가 필요한 작업은 그 계약을 따른다.
2. 터미널이 있는 Codex·Claude Code에서는 **로컬 Composio CLI**를 우선한다. 터미널이 없거나 CLI를 사용할 수 없으면 호출 가능한 승인된 hosted Composio 도구를 확인한다. 사용자가 hosted를 요청했거나 필요한 기능이 hosted에만 있는 경우도 그 경로를 사용한다. 사용할 수 없는 도구를 실행했다고 표현하지 않는다.
3. 사용 가능한 `composio`·`composio-cli` 지침이 있으면 해당 경로의 사용법을 읽는다. 알려진 도구는 바로 스키마·입력을 확인하고, 모르는 도구만 검색한다. 같은 작업에서 확인한 도구·계정은 재사용하되 쓰기 대상과 권한은 최신 상태로 확인한다.
4. 연결이 있다는 사실만으로 충분하다고 보지 않는다. 실제 서비스 계정, 조직·워크스페이스, 대상 저장소·팀·채널과 필요한 권한을 확인한다. 복수 계정이면 지정 계정을 명시적으로 선택한다. 필요한 계정이 불명확하고 연결 자료에서도 해소되지 않을 때만 사용자에게 묻는다.
5. 기능 부재·대상 계정 불일치·권한 부족·사용 불가가 확인되면 이유를 짧게 알리고 기존에 승인된 서비스 CLI·API·브라우저 경로를 사용한다. **대체 경로에서도 4항의 신원·대상·권한 확인을 다시 수행**하며 CLI의 기본 활성 계정을 그대로 신뢰하지 않는다. 댓글·리뷰 게시, push, 병합 등 실제 수행할 작업별 권한을 확인하고, 단순히 호출이 성공한다는 이유로 지정되지 않은 계정을 사용하지 않는다. 지정 신원을 확정할 수 없으면 해당 쓰기는 중단·보고한다. 연결이 없는 경우 현재 작업에 맞는 기존 인증 경로가 있으면 이어가고, 새 계정 연동·로그인이 필요하면 사용자 인증을 요청한다. 접근 제한이나 필수 승인 절차를 우회하지 않는다.

## 로컬 CLI의 최소 사용법

설치된 CLI의 `--help`와 실제 도구 스키마를 기준으로 사용한다. 아래는 조회·입력 확인 예시이며, 실행하려는 작업의 도구를 확인해 대체한다.

```bash
composio execute GITHUB_GET_THE_AUTHENTICATED_USER -d '{}'
composio search "create a github issue" --toolkits github
composio execute GITHUB_CREATE_AN_ISSUE --get-schema
composio execute GITHUB_CREATE_AN_ISSUE --dry-run -d @issue.json
```

실행 데이터는 `-d @파일.json` 또는 표준입력으로 전달한다. 복수 계정은 현재 CLI가 지원하는 `--account`로 지정한다. 스크립트·조건 분기가 필요하면 `composio run`, 전용 도구가 없는 API 작업은 지원되는 `composio proxy`를 확인한다. 도구 slug·필드·옵션을 추측하지 않는다. `--dry-run`은 실제 서비스 실행·권한·성공의 증거가 아니다.

## 쓰기 결과와 인증 정보

- 쓰기 전에 대상·내용·발신 신원·승인 범위를 확정하고 한 경로로 실행한다. 여러 조율자·도구가 같은 쓰기를 중복 수행하지 않는다.
- 타임아웃·네트워크 오류·큐 접수 등으로 결과가 불명확하면 **대상 상태나 실행 기록을 조회해 먼저 대조**한다. 불확실한 쓰기를 hosted·CLI·직접 API 등 다른 경로로 자동 재전송하지 않는다. 실행되지 않았음이 확인되면 승인 범위 안에서 재시도하고, 확인할 수 없으면 pending으로 남긴다.
- 생성된 객체 ID·링크, 스레드 root, 대상 SHA 등 다음 작업에 필요한 결과만 기록한다. 실제 전송·갱신·병합을 확인한 뒤 완료로 보고하며 큐 접수나 도구 호출 수락과 구분한다.
- 기존 Composio 연결의 인증을 재사용한다. Composio가 연결됐다는 이유로 서비스 토큰을 별도로 수집하지 않는다. 지정된 별도 경로에 환경변수가 필요하면 프로젝트의 비밀 저장소 계약을 따른다. 토큰·OAuth 비밀·원시 인증 헤더를 출력하거나 스킬·PR·로그에 복사하지 않는다.

이 스킬은 연결을 설치하거나 갱신하는 스케줄러가 아니다. 서비스별 작업 절차·Linear 상태·독립 리뷰·제이지 알림·worktree 정리의 조건은 해당 작업 스킬과 현재 사용자 지시를 그대로 따른다.
