# Linear Create

대화와 계획 맥락을 정리해 Linear 이슈 하나를 만들고 필요하면 승인된 관련 프로젝트 문서와 연결한다. 독립적인 상태 변경·조회 작업과 PRD 일괄 생성은 이 스킬 범위가 아니다.

## 규칙

1. **담당자 기본값은 이 워크스페이스의 본인(JAY 워크스페이스에서는 Jay)**이다. 다른 사람에게 줄 때만 `--assignee <userId>`를 준다. 이름→id 변환은 하지 않는다(동명이인 위험).
2. **완료(`completed`)·취소(`canceled`) 상위 이슈 아래에는 만들지 않는다.** `--parent`의 부모가 이 상태면 생성 전에 중단한다. 부모는 쓰기 전에 항상 조회한다.
3. **팀은 추정하지 않는다.** `--team <KEY>`(예: `JAY`)를 주거나 `LINEAR_TEAM_ID`를 설정한다. 둘 다 없으면 중단한다.

## 절차

1. 대화 맥락과 접근 가능한 관련 계획·Traycer artifact·코드·기존 이슈를 살펴 제목과 작업 내용을 정리한다. 명시된 저장소·프로젝트·계정과 승인 범위를 확인한다. 확인하지 못한 원문이나 추정은 사실로 쓰지 않는다.
2. 아래만 확인한다(AskUserQuestion, 한 번에 묶어서):
   - 제목
   - 상위 이슈 (`--parent`, 없으면 독립 이슈)
   - 담당자 — 기본 본인, 바꿀 때만 userId
   - 팀 — 환경에 `LINEAR_TEAM_ID`가 없을 때만
3. 아래 작업 인계 기준에 맞춰 본문과 필요한 관련 문서를 준비한 뒤 실행한다. 확인 질문에 이미 답이 있으면 다시 묻지 않는다.
4. 생성 결과를 재조회해 본문·대상·문서 링크를 확인한다. 문서를 연결했다면 같은 접근 경로로 문서 본문도 읽어 이슈에서 따라갈 수 있는지 확인한다. 다른 계정이나 실행 환경의 접근은 별도로 확인한 경우에만 보장한다.

## 구현 가능한 이슈와 기획 인계

코드 작업 이슈라면 실행자가 Linear에서 작업의 목적과 범위를 파악하고 실제 저장소를 확인해 착수할 수 있도록, 해당되는 항목만 간결하게 적는다.

- 배경·원하는 결과, 대상 저장소와 기준 브랜치(확인된 경우), 변경 범위·비범위, 승인된 결정과 제약.
- 관찰 가능한 완료 기준과 검증 방법, 관련 코드·기존 테스트, 선행 작업·관련 이슈·PR. 현재 상태나 버전은 확인 시점을 명시하고 실행 전에 재확인하도록 한다.
- 결정이 필요한 사항, 미확인 사실, 외부 접근·계정·환경 제약은 명시한다. 일반적인 구현 판단까지 사용자 결정으로 만들지 않는다.
- 원본을 확인한 Traycer 계획·TODO·검토에서 구현에 필요한 결정, 미결 항목과 완료 기준을 Linear에 옮긴다. 단순 링크만으로 필수 맥락을 대체하지 않는다. 출처·기준 시점을 기록하고, 기존 이슈와 충돌하거나 원본이 오래됐으면 차이를 드러낸다.

여러 이슈가 공유하는 상세 기획이 있고 해당 Linear 프로젝트와 쓰기 권한이 확인되면 기존 프로젝트 문서를 먼저 찾아 재사용한다. 필요한 경우에만 사용자가 승인한 범위에서 프로젝트 문서를 만들고, 공통 배경·결정 근거·서비스별 의존성·검증을 기록한다. 이슈 본문 상단에 문서 링크와 작업에 필요한 요약을 넣는다. 단일하고 작은 이슈는 별도 문서 없이 본문에 충분히 적는다. 연결할 프로젝트가 불명확하거나 문서를 만들 수 없으면 추정하지 말고 이슈에 가용한 맥락을 기록하고 한계를 보고한다.

Traycer artifact는 접근 가능한 공유 링크가 확인된 경우 출처로 연결한다. 로컬 경로나 비공유 artifact만 있으면 다른 에이전트가 열 수 있다고 주장하지 말고, 필수 내용을 Linear에 남긴다. Linear 문서 링크 및 본문을 실제 재조회하고, 다른 계정·환경의 접근은 별도 확인 여부를 구분한다. 문서 생성·연결이 코드 구현·커밋·배포 승인을 뜻하지 않는다.

이슈와 문서가 충분해도 실제 저장소 접근·브랜치·의존성·승인·선행 조건까지 확보됐다는 보장은 없다. 실행자는 착수 시 이를 확인하고 차단되면 구체적 원인을 보고한다.

## 실행

```bash
python3 ~/.claude/skills/linear-create/scripts/linear_create.py "<제목>" "<설명>" \
  --team JAY [--parent JAY-543] [--assignee <userId>] [--priority 1-4] [--project <id>] [--label <id>]
```

실행 경로는 Composio다. `composio` CLI에 로그인되어 있어야 하며, 계정은 `linear_valsa-tenino`("Jay's workplace")가 기본이다. 다른 계정을 쓸 때만 `LINEAR_COMPOSIO_ACCOUNT`를 설정한다. API 키는 필요 없다.

## 출력

```
✅ 이슈 생성 완료
   JAY-600: <제목>
   🔗 https://linear.app/...
```

실패 시 이유를 한 줄로 보여 주고 `❌`로 끝낸다. 예:
- `부모 JAY-543가 '완료' 상태입니다. 완료·취소된 이슈 아래에는 하위 이슈를 만들 수 없습니다.` → 상위를 바꾸거나 독립 이슈로 만들지 확인한다.
- `팀이 없습니다.` → `--team`을 준다.
