# 모델과 위임 계약

## 정책 파일과 계산

역할별 하네스·모델·추론 수준은 [policy.json](../policy.json)과 `scripts/resolve.py`가 정한다. 이 문서에는 모델 표를 두지 않는다. 숫자나 모델을 바꾸려면 정책 파일을 고치고, 한 기기에서만 다르게 쓰려면 `~/.traycer/workflow-policy.json`에 바꿀 키만 적는다.

```bash
python3 scripts/resolve.py --project seoulseeing --lane M
python3 scripts/resolve.py --project core-ser --lane L --exhausted claude
python3 scripts/preflight.py --project seoulseeing < issue.json
```

출력의 `roles`가 역할별 배정, `limits`가 리뷰 횟수·토큰·세션 상한과 멈출 지점, `notes`가 전환 사유, `wait`가 채울 수 없는 역할이다. 종료 코드 3은 대기다. 조율자는 출력을 작업 계약에 그대로 적고 각 세션의 ID를 덧붙인다. 위임마다 다시 계산하되 이미 실행 중인 세션은 바꾸지 않는다. 사용자가 명시한 모델은 계산 결과보다 우선하며 그 사실을 계약에 적는다.

계산 순서는 다음과 같다.

1. **구현 계열:** 프로젝트의 기본 계열(`projects.<이름>.primary`)이 먼저고 나머지 계열(Claude ↔ Codex)이 다음이다. 야간 중국 모델 조건이 맞으면 Qwen이 맨 앞에 온다. 소진되지 않은 첫 계열을 쓴다.
2. **등급:** 가벼움·표준·무거움 세 등급이다. S·M 구현은 표준, L 구현은 무거움이다. 계열을 바꿔도 등급은 유지하며 낮추지 않는다.
3. **계획 critique:** 구현 계열과 다른 계열에서 고른다. 야간 중국 모델 구성이면 DeepSeek이 먼저다.
4. **최종 리뷰:** 구현 계열과 다른 계열에서 고른다. 중국 모델을 쓸 수 있으면 Qwen이 먼저고, 구현이 Qwen이면 DeepSeek이 먼저다. 그다음은 Claude·Codex의 무거운 등급이다.
5. **조율자:** 야간에도 주간 계열의 표준 등급을 유지한다.

추론 수준은 등급이 정한다. `xhigh`는 무거운 등급에만 쓴다. 지원되지 않는 추론 수준은 넘기지 않는다.

## 야간 중국 모델 스위치

스위치는 하나다. `~/.traycer/night-roster.sh on|off|auto|status`가 `~/.traycer/night-roster.env`에 값을 쓰고 `resolve.py`가 그 파일을 읽는다.

| 값 | 구현·테스트·critique | 최종 리뷰 |
| --- | --- | --- |
| `auto` | 23:00~09:00 KST에만 Qwen·DeepSeek | Qwen 우선 |
| `on` | 시각과 무관하게 Qwen·DeepSeek | Qwen 우선(구현이 Qwen이면 DeepSeek) |
| `off` | 주간 계열만 | Claude·Codex만. 어느 역할에도 중국 모델을 쓰지 않는다 |

- 야간 시간은 Qwen·DeepSeek 할인 구간(UTC+8 22:00~08:00)과 같다. 위임 시점의 시각으로 판정하고, 시각을 알 수 없으면 주간으로 본다.
- **L 줄의 구현·테스트·critique는 스위치와 무관하게 중국 모델을 쓰지 않는다.** 복구하기 어려운 변경을 할인 모델에 맡기지 않기 위해서다.
- 프로젝트별로 막으려면 정책의 `projects.<이름>.cn_allowed`를 `false`로 둔다.
- Qwen·DeepSeek 세션은 모두 Qwen Code 하네스로 만든다.
- **중국 모델이 구현한 실행은 배포하지 않는다.** PR 병합까지가 한계이며 배포는 주간 구성이나 사용자의 명시적인 승인으로만 한다.
- 야간에 승인 범위를 넘는 결정이 필요하면 `needs-confirm`으로 넘기고 그 이슈만 멈춘다. 구현 방향·모호한 요구 해석처럼 승인 범위 안의 선택은 근거를 기록하고 진행한다.

## 독립성

**작성자와 검토자는 다른 계열이다.** 계획 작성 계열과 critique 계열, 코드 작성 계열과 최종 리뷰 계열이 달라야 한다. Qwen과 DeepSeek은 서로 다른 계열로 본다.

- 최종 리뷰어는 계획·critique·구현·테스트·원인 분석에 참여하지 않은 새 세션이다. 같은 모델이 critique와 리뷰를 맡더라도 세션은 분리한다.
- 구현을 맡은 조율자를 독립 검증자나 최종 리뷰어로 세지 않는다.
- 다른 계열을 쓸 수 없으면 S·M 줄에서만 같은 계열의 무거운 등급을 새 세션으로 쓴다. 출력에 `same_family: true`가 붙고, 계약과 PR 리뷰에 "작성자와 같은 계열"이라고 적는다. L 줄은 대기한다.
- 완료되지 않은 검토자를 필수 인원에 포함하지 않는다.

## 계획 critique의 관점

M 줄의 1명은 아래 세 묶음을 모두 본다. L 줄의 3명은 한 묶음씩 맡아 다섯 관점을 빠짐없이 다룬다.

| 담당 | 관점 |
| --- | --- |
| 1 | 요구사항·범위·완료 기준과 명확성·모순·빠진 상태·복잡성 |
| 2 | 기술 설계·실패 처리·의존성과 운영·권한·데이터·재시작·되돌림 |
| 3 | 재현·테스트·회귀·관측 가능성 |

검토자는 배정된 관점을 실제 코드와 계획에 대조하고 발견과 미검토 범위를 보고한다. 범위가 지나치게 넓으면 조율자가 근거를 기록하고 인원을 추가할 수 있다.

## 실행 모델 확인

Claude는 `sonnet`·`opus`·`haiku` 별칭으로 세션을 만들고 정책의 `expect_version`(5.5)을 기대한다. 그 밖의 계열은 정책의 정확한 모델 ID로 만든다.

결과 수락과 리뷰 게시 전에 `traycer_get_transcript`로 기여한 assistant 턴의 `provider`·`model`을 확인해 계약에 적는다. `traycer_list_agents`는 설정값이므로 단독 근거가 아니고 보고자의 모델 문자열도 충분하지 않다.

- 실제 모델이 배정과 다르면 그 결과를 수락하지 않고 배정된 모델로 다시 수행한다.
- transcript가 별칭만 보여 주고 버전을 알 수 없으면 "별칭만 확인"이라고 적는다. S·M 줄은 이 기록을 남기고 진행한다. L 줄은 해당 역할을 hold하고 보고한다.
- 더 오래된 버전으로 자동 하향하지 않는다.

## Traycer 세션 생성과 응답

1. `traycer_create_agent`는 **같은 호스트에서 `surface: "gui"`, `routing: "hold"`를 명시**해 호출한다. remote host나 terminal child에 같은 routing 보장이 있다고 가정하지 않는다. 현재 작업에 허용된 프로필을 명시한다. fast mode는 사용자나 가이드 지시가 있을 때만 켜고 권한 모드는 가이드에 별도 지시가 없으면 `full_access`를 사용한다.
2. 생성 후 하네스·모델·프로필·workspace를 확인하고 hold 설정 요청·응답을 기록한다. 실제 실행 모델은 [실행 모델 확인](#실행-모델-확인)에 따라 대조한다. 조율자가 **결과 수락과 매 리뷰 게시 직전 `traycer_get_transcript`로 해당 결과의 assistant 턴 `provider`·`model`·turn ID를 확인**해 선택한 정확한 모델과 대조한다. 여러 턴의 결과면 기여한 턴들을 확인한다. `traycer_list_agents`는 설정값이므로 실제 실행 모델의 단독 근거가 아니며 보고자의 모델 문자열도 충분하지 않다. 모델이 다르면 해당 결과를 미검증으로 두고 요구 모델에서 다시 수행한다. transcript의 실행 메타데이터를 읽을 수 없으면 출처 확인 대기로 남기며 같은 검토를 맹목 반복하지 않는다. provider-native subagent가 Traycer 설정을 이어받는다고 가정하지 않는다.
3. `traycer_send_message`에 **`expectReply: true`**를 지정해 작업을 전달한다. 새 에이전트 생성만으로 실제 작업이 시작되거나 끝난 것으로 보지 않는다.
4. 배정된 모든 critique는 같은 계획 버전을 받되 서로의 결과에 영향을 받지 않도록 한다. 테스트 작성자와 구현자가 같은 파일을 동시에 수정하지 않게 한다. 리뷰어·실행 검증자는 원격 대상 SHA를 fetch한 별도의 깨끗한 체크아웃을 사용한다.
5. 단계 전환·새 위임 직전과 응답 수락 시 최신 Linear 보류·취소·소유를 재확인한 뒤 작업·시도·실제 모델·SHA·보고를 대조한다. 보류면 로컬 후속 작업과 외부 쓰기를 중단한다. [리뷰 반복·재개 계약](review-loop.md)에 따라 결과를 다음 실제 실행으로 연결한다. 비동기 응답만 남으면 요청의 `expectReply: true`·응답 세션·다음 행동이 기록됐는지 확인하고 polling하거나 대기 턴을 유지하지 않고 현재 진행을 보고한 뒤 응답으로 재개한다.
6. 세션 ID와 시도별 상태를 프로젝트 작업 기록에 보존한다. 완료되고 재사용하지 않을 세션은 활성 작업·셸이 없는지 확인 후 정리한다.

Traycer child에게 구현·TC·검증을 맡길 때 가용한 `traycer-implement`를 적용하도록 한다. 자기 코드를 자신이 독립 검토했다고 보고하지 않게 한다.

## 새 작업의 메시지와 조율

진행 중인 이슈·PR의 기존 보고 계약은 유지한다. 새 작업에서는 아래 위임 항목을 한 번에 전달하고, 긴 원문·로그는 접근 가능한 경로와 필요한 요약으로 연결한다. 계획 critique의 동일 버전·독립성, 검증 원본과 실제 증거는 그대로 제공한다.

결과, 판단이 필요한 차단, 다른 담당자에게 영향을 주는 결정·인터페이스 변경은 바로 알린다. 단순 수신 확인·감사 답장·반복 상태 보고는 기본 생략하거나 결과에 합친다. 응답을 요청받았거나 계약·도구·사용자가 회신을 요구하면 반드시 답하고, 최종 결과와 미검증 사항도 빠뜨리지 않는다. 조율자는 의존성과 다음 담당자를 명시하고 비동기 응답으로 재개하며 불필요하게 재촉하거나 polling하지 않는다. 필수 Slack·PR 보고와 hold·소유·head 확인은 유지한다.

## 토큰·캐시 비용 규칙

- 조율자는 자식 세션에 일을 전달하고 응답이 와야 진행되는 지점에서 턴을 끝낸다. 자식 응답을 기다리며 턴을 열어 두거나 짧은 간격으로 확인하지 않는다. 상태는 대화가 아니라 run manifest·receipt·작업 기록 파일에 두고 재개 때 그 파일에서 읽는다.
- 각 하위 세션에는 역할에 필요한 부분만 전달한다. 스킬·참조 전체나 계약서 전문을 모든 세션에 다시 읽히지 않는다. 역할·모델·SHA·완료 기준·허용 파일·보고 형식과 해당 역할의 규칙 발췌만 준다. 원문·로그는 경로로 연결한다.
- 하위 세션은 계약에 정한 역할만 만든다. 같은 역할의 중복 세션, 요약·진행 감시 전용 세션, 범위 없는 재검토 세션을 추가하지 않는다. 완료되어 재사용하지 않는 세션은 활성 작업이 없는지 확인한 뒤 정리한다.
- 한 세션의 컨텍스트가 정책의 `session_context_cap`을 넘거나 단계가 바뀌면 결정·SHA·남은 일을 파일로 넘기고 새 세션에서 이어간다. 긴 세션은 매 호출마다 전체 컨텍스트를 다시 읽으므로 비용의 대부분을 차지한다.
- 이슈에 쓴 토큰이 `limits.token_cap`을 넘으면 새 위임을 멈추고 `needs-confirm`으로 넘긴다.
- 작업 기록에 역할별 모델·추론 수준·세션 ID를 남긴다. 사용량을 읽을 수 있으면 입력·캐시 입력·출력을 역할별로 함께 남겨 다음 등급 조정의 근거로 쓴다. 읽을 수 없는 값은 미확인으로 둔다.

## 매 위임에 전달할 내용

- 역할·모델·추론 수준·허용 프로필·`routing: "hold"`, 현재 승인 범위.
- Linear 원본·계획 버전·저장소·전용 체크아웃·기준 브랜치·검토 SHA.
- 기존 실행 계약의 승인 범위·리뷰 전용 여부·미해결 지적·현재 단계·결과 수신 후 다음 행동. 부모와 child가 서로 상대방의 수정 착수를 기다리지 않게 담당자를 하나로 정한다.
- 수정 가능한 파일·금지 영역·다른 작업자의 범위.
- 완료 기준·관련 TC·실행할 검사·필요한 테스트 코드.
- 결과를 남길 프로젝트 경로·응답 대상·보고 필드. 증거는 삭제 예정 worktree 밖에 보존하고 Slack 발송·worktree 삭제는 조율자만 수행한다.
- 재위임에도 동일한 모델·독립성·TC·증거 규칙 적용.
- 환경변수는 Doppler `jay/shared` 우선 조회 규칙을 전달한다. child에는 키 이름·필요한 제한된 실행 경로·capability만 전달하며 서비스 비밀 전체를 복사하지 않는다.
- **외부 쓰기는 조율자만 담당.** child는 결과를 보고하고 직접 push·Linear/PR/Slack 쓰기나 worktree 삭제를 하지 않는다. 사람이 hold·취소한 경우 후속 작업·외부 쓰기를 중단하는 규칙도 전달한다.

보고는 `역할 / 실제 실행 모델·프로필·시도 식별 근거 / 계획 버전 또는 SHA / 변경·발견 / TC·테스트 경로 / 실행 명령·종료 코드 / 실패·미검증 / 결과 경로`를 포함한다. 조율자는 원자료·실행 메타데이터와 대조하며 보고 문구만으로 통과시키지 않는다.

## 사용량 소진과 계열 전환

rate limit·네트워크·하네스 실패가 나면 먼저 해당 시도의 실제 종료·결과·전달 상태를 확인한다. 살아 있는 작업이나 결과가 불명확한 쓰기를 복제하지 않는다. 일시 오류면 같은 설정으로 한 번 다시 시도한다. 사용량 소진이면 아래 순서로 전환한다.

1. **이슈 착수 전:** `traycer_list_provider_profiles`의 상태가 소진이면 그 계열을 `--exhausted`로 넘겨 처음부터 다음 계열로 계약을 만든다. 같은 계열에 작업에 허용된 다른 프로필이 정상이면 프로필만 바꾸고 계열은 유지한다. 다른 회사·워크스페이스 연결, 새 유료 계정, 승인된 비용 한도 밖의 프로필은 쓰지 않는다.
2. **실행 도중:** 소진된 세션을 `traycer_stop_agent`로 멈추고 실행·예약·소유 프로세스가 끝났는지 확인한다. 확인할 수 없으면 교체하지 않고 대기한다. 그 세션의 커밋과 미커밋 변경을 보존한다. `--exhausted`와 `--switches`를 넣어 다시 계산하고, 인계 파일(계획 버전, 마지막 커밋 SHA, 남은 일, 미해결 지적)을 만들어 새 계열의 세션에 넘긴다. 같은 작업 폴더를 두 세션이 동시에 쓰지 않는다.
3. **기록:** 계약에 `fallback: {역할, from, to, 사유, 시각}`을 남기고 정본 세션 ID를 갱신한다. 교체된 시도의 뒤늦은 결과는 수락하지 않으며, 그 시도로 작업 메시지를 다시 보내지 않는다. 멈춘 시도가 다시 실행 중이면 중지하고 종료를 확인한다.
4. **전환 뒤 독립성:** 코드를 쓴 계열이 바뀌었으므로 최종 리뷰어를 다시 계산한다. 이미 그 계열이 리뷰어였다면 다른 계열의 새 리뷰 세션을 쓴다. 계획이 바뀌지 않았으면 계획 critique는 다시 받지 않는다. 새 구현 세션이 계획을 실질적으로 고치면 그 계열과 다른 계열의 critique를 다시 받는다.
5. **상한:** 한 이슈의 전환은 정책의 `fallback.max_switches_per_issue`번까지다. 넘으면 대기한다.
6. **대기:** 계산이 `wait`를 돌려주면 그 단계를 대기로 기록하고 현재 채팅에 이유와 가장 빠른 회복 시각을 남긴다. 같은 설정을 맹목 반복하거나 한도 회복까지 턴을 붙잡지 않는다. 대기가 `fallback.notify_after_wait_hours`를 넘길 것으로 보이면 그때 알린다.

세션은 계속 `routing: "hold"`로 만든다. Traycer의 자동 라우팅에 맡기면 검토 세션이 작성자와 같은 계열로 바뀌어도 기록이 남지 않는다. 전환은 조율자와 실행기가 정책의 순서대로 하고 기록한다. Qwen·DeepSeek은 사용량을 미리 읽을 수 없으므로 한도 오류가 실제로 났을 때 소진으로 본다.
