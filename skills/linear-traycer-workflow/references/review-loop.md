# 리뷰 반복과 재개 계약

## 작업 모드를 이어받는다

대상 저장소·이슈·PR·소유 조율자와 현재 사용자 지시, 해당 작업의 기존 계약을 함께 읽는다. 실행 계약은 한 채팅 메시지보다 오래 유지되며 새 세션·하위 위임에도 전달한다. 다른 이슈·프로젝트의 승인을 끌어오지 않는다.

- 기존 구현·수정 실행이 승인된 작업의 후속 리뷰는 `확인 → 수정 → 독립 검증 → Opus 재리뷰 → PR 기록`을 이어간다. 새 PR을 만드는 단계나 전체 계획 critique를 처음부터 반복할 필요는 없다. 계획의 실질 변경·구현 계열 변경 때만 기존 규칙대로 계획을 재검토한다.
- 기존 실행 승인이 없는 리뷰 요청, 또는 명시적인 리뷰 전용·수정 금지는 발견과 근거만 전달한다. 이 스킬의 존재를 수정·병합 권한으로 삼지 않는다.
- PR까지 승인된 계약은 수정·검증·재리뷰가 끝난 열린 PR을 인계한다. 병합까지 승인됐다면 검사·리뷰 통과 뒤 재승인 없이 병합한다. 두 계약을 섞지 않는다.

## 결과가 오면 전진한다

리뷰·테스트 보고 수신은 완료가 아니라 다음 전환의 입력이다. 조율자는 최신 hold·소유·대상 SHA를 확인하고 다음 행동을 같은 턴에 시작한다.

1. 리뷰 발견을 항목별로 대조해 유효·오탐·범위 밖으로 판정하고 근거와 처분을 남긴다. "차단 없음"이어도 현재 변경의 유효한 결함이 남아 있으면 해결한다. 단순 취향 제안을 모두 결함으로 채택하지 않는다.
2. 범위 안의 유효한 결함은 지정 구현자가 수정하고 필요한 회귀 테스트를 작성·보강한다. 조율자가 실제 위임한 세션·요청을 기록한다. 결과를 요약하는 것만으로 수정 작업을 시작했다고 하지 않는다.
3. 수정 SHA에서 독립 검증자가 영향받는 테스트·필수 검사를 실행한다. 실패하면 원인 분류 후 범위 안의 수정으로 돌아간다. 통과하면 조율자가 push하고 최종 원격 head를 Opus에게 재리뷰한다. 같은 SHA의 여러 검사라도 작업 공간·자원을 공유하면 직렬 실행한다.
4. 라운드별 발견·처분·검증과 리뷰를 PR에 게시한다. 새 지적이 있으면 1로 돌아간다. 없으면 최종 head 게이트를 대조하고 승인된 인계 또는 병합·상태 갱신·정리·알림을 수행한다.

기술 판단이 갈리면 재현·코드·테스트 근거를 먼저 대조하고 필요할 때 새 독립 의견으로 해소한다. 범위 안에서 해결 가능한 논쟁을 곧바로 사용자 승인으로 넘기거나 무근거로 무한 재리뷰하지 않는다. 실제 제품·범위 결정이 필요한 경우에만 남은 선택을 구체적으로 묻는다.

## 대기를 구분하고 재개 경로를 남긴다

기존 프로젝트 기록에 현재 단계, 라운드·head, 미해결 발견·처분, 다음 행동·담당자, 결과를 받을 세션·요청 식별자, 대기 사유·재개 조건을 남긴다. 새 runner·JSON 스키마 설치를 의무화하지 않는다.

- **실행 가능:** 조율자가 지금 처리할 다음 행동이 있으면 실행한다. 이미 승인된 수정·검증·병합을 next-step 버튼으로 사용자에게 돌려주지 않는다.
- **결과 대기:** `expectReply: true`로 실제 전달된 작업과 응답할 세션을 확인한다. 조율자는 polling·단순 대기 턴을 유지하지 않고 진행 보고 후 턴을 끝낸다. 응답이 오면 작업 식별자·시도·head·실제 모델을 대조하고 다음 행동을 시작한다. 응답 대기는 사용자 결정을 기다리는 상태가 아니다.
- **CI·사용량·기술 장애 대기:** 실제 장애 근거와 사용할 수 있는 재개 경로를 남긴다. 필수 CI처럼 child 응답이 아닌 외부 사건은 기존 runner·지원되는 알림 등 확인된 경로를 사용한다. 그런 경로가 없으면 자동 재개가 보장된다고 말하지 말고 현재 한계와 필요한 복구를 보고한다. 결과 불명확한 쓰기나 살아 있는 작업을 복제하지 않는다.
- **사용자 결정·hold:** 중단 근거가 되는 최신 지시·작성자·시각·이유와 필요한 해제 조건을 확인한다. 사람이 건 hold·취소·완료·소유 충돌은 기존 중단 규칙을 따른다. 같은 PR에 "리뷰해줘"라는 말만으로 별도 hold를 해제하지 않는다. 조율자가 검증 실패를 기록한 기술적 대기라면 사용자 hold로 격상하지 않고 승인 범위 안에서 원인을 해결한다. 출처·해제 권한이 불명확하면 보존하고 그 불명확성만 결정 대상으로 보고한다.

cron은 새 이슈 선택과 중복 방지의 계기다. 실행 중인 PR 수정 반복을 다음 cron이 대신 이어준다고 가정하지 않는다. 활성 run은 기존 조율자·결과 전달 경로로 이어가며 대기 중인 run을 완료 영수증으로 닫거나 슬롯을 비워 중복 dispatch하지 않는다. 예약 설치만 승인된 요청을 이슈 구현·병합 승인으로 확대하지 않는다.

종료 보고는 승인된 인계·병합·완료 증거가 있을 때 한다. 그 전에 턴을 끝낸다면 결과 대기인지 실제 장애·결정 대기인지와 이미 연결된 다음 행동을 명확히 남긴다. "곧 계속하겠다"는 약속만으로 자동 재개가 연결된 것은 아니다.
