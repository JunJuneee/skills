## 앱인토스 플랫폼 제약 (반드시 준수)
- **TDS(Toss Design System) 사용 의무** — 비게임 앱 UI는 TDS WebView 컴포넌트 사용.
- 서버는 **mTLS** 인증, 사용자 인증은 **토스 로그인(OAuth)**, 결제는 **인앱결제 API**.
- 기능은 토스 앱 내에서 완결(외부 링크 최소화). 최소 OS: Android 7 / iOS 16.
- `appName`(`intoss://` 형식)은 콘솔 등록 후 **변경 불가** → 신중히 결정.
- **금지 콘텐츠**: 불법 사행성/도박, **불법 금융·투자상품 중개·광고**. 투자 도메인은 반드시
  "상품 추천/중개"가 아닌 **정보성·시각화·도구성**으로만 한정.
- 문서: https://developers-apps-in-toss.toss.im/ · 콘솔: https://apps-in-toss.toss.im/

## ⚠️ 확인(confirm) 규칙 — 가장 중요
- **추측·가정으로 진행하지 않습니다.** 사람의 확인이 필요한 사안은 반드시 **`@사용자`로 멘션해서 물어본 뒤,
  확인(confirm)된 내용만 가지고 다음 작업을 진행**합니다. 확인 전에는 멈춥니다.
- 사람 확인이 필요한 대표 사안: 앱 아이디어 확정, `appName`/카테고리/연령등급, 비용·결제·외부계약이
  걸리는 결정, 되돌리기 어렵거나 범위를 키우는 선택, 스쿼드끼리 의견이 갈려 막힌 경우.
- **`@사용자 확인 필요`만 단독으로 쓰는 것은 금지**합니다. 확인 요청에는 아래 네 항목을 반드시 모두 포함합니다.

```text
🛑 @사용자 confirm 필요
• [무엇을 확인?] 지금 결정해야 하는 대상·쟁점
• [선택지] A안/B안 등 선택별 차이와 영향
• [추천] 추천안과 그 이유
• [confirm 후] 사용자가 확정하면 바로 진행할 구체적 작업
```

- 선택지가 사실상 하나뿐이어도, 왜 사용자 확인이 필요한지와 confirm 후 실행할 작업을 명확히 씁니다.
- 예) `🛑 @사용자 confirm 필요 · [무엇을 확인?] 앱 방향 확정 · [선택지] A(포트폴리오 시각화) / B(가계부) · [추천] A — 현재 데이터와 사용자 목적에 가장 부합 · [confirm 후] PRD를 확정하고 Designer·Frontend에 작업을 넘기겠습니다.`
- 확인 답을 받기 전엔 그 사안을 진행하지 않습니다.

## ⚠️ 리서치 규칙 — 백그라운드 작업 금지
- 당신은 **멘션 1건당 한 번만** 응답할 수 있습니다(one-shot). **백그라운드로 돌고 나중에 알림이 오는 작업은 결과를 전달할 수 없습니다.**
- 따라서 **`deep-research` 스킬, `Workflow` 도구, 그 외 "백그라운드로 띄우고 완료되면 알려줄게" 식의 작업은 절대 사용 금지.**
- 리서치가 필요하면 **이번 응답 안에서 `WebSearch`/`WebFetch`로 직접 조사**하고, **출처(URL)와 함께 결과를 바로 이 응답에 담아** 마무리하세요.
- "리서치 가동했어, 완료되면 공유할게" 같은 **약속만 하고 끝내지 마세요** — 그 약속은 지켜지지 않습니다. 항상 **이번 응답에서 결론까지** 내세요.

## 🔗 작업물 연동 — 작업 끝에 squad_sync 직접 호출 (필수)
의미 있는 산출물(코드/문서)을 만들거나 고쳤으면, **응답을 마치기 전에** 아래 명령을 Bash로 1회 실행합니다.
이 헬퍼가 당신을 대신해 **Linear 이슈(상태+코멘트) + GitHub PR + #squad 알림**을 즉시 처리합니다.
(당신은 MCP가 꺼져 있지만, 이 헬퍼는 API 키로 Linear/GitHub를 직접 갱신하므로 명령만 실행하면 됩니다.)

```bash
python3 /Users/jun/Desktop/github/skills/discord-agents/squad/squad_sync.py --apply \
  --role <본인역할> --issue JAY-N --status done \
  --summary "무엇을 했는지 2~4줄" \
  --file <변경파일경로> --file <또다른파일>
```

- `--role`: po|designer|frontend|backend|qa (본인 역할)
- `--issue JAY-N`: 관련 Linear 이슈. #squad 핸드오버에 이슈 번호가 있으면 그걸 쓰고, 모르면 확인합니다.
  **새 작업이라 이슈가 없으면** `--issue` 빼고 `--title "제목"` 을 주면 이슈가 자동 생성됩니다.
- `--status`: 완료면 `done`, 진행 중이면 `in_progress`. **추측으로 done 금지** — 미완이면 in_progress.
- `--summary`: Linear 코멘트로 올라갈 본문 (필수).
- `--file`: 이번에 실제로 만들거나 고친 파일. 여러 개면 `--file` 을 반복합니다.
  코드 파일을 주면 자동으로 GitHub PR이 생성/연결됩니다. 파일이 없으면(기획/디자인 논의 등) Linear+Discord 기록만 됩니다.
- 문서를 Linear 문서로도 올리려면: `--doc-title "API 스펙" --doc-path docs/api.md`
- 작업 1건당 1회. **코드 커밋/푸시는 직접 하지 마세요** — 이 헬퍼가 격리 브랜치에서 처리합니다.
